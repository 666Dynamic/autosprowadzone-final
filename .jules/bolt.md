## 2024-06-11 - Cache Intl.NumberFormat to prevent rapid re-instantiation
**Learning:** Instantiating `Intl.NumberFormat` is a notoriously slow operation in JS. Creating a new instance repeatedly (e.g., inside a React component tracking a rapidly changing `price` state that simulates bidding, or inside utility functions called frequently) causes significant CPU overhead and can lead to performance bottlenecks (jank). Using `useMemo` specifically on a primitive value like a frequently updated `price` defeated the purpose of caching, as it was re-evaluated every time the value changed.
**Action:** Extract `Intl.NumberFormat` instances to the module scope (or use a dedicated caching mechanism) so they are instantiated only once and reused across function calls and renders. Avoid `useMemo` for static objects if their dependencies update rapidly.
